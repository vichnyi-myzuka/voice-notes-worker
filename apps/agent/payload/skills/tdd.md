name: tdd
description: Use when implementing a feature or fixing a bug in code that has (or should have) automated tests: work in small red-green-refactor steps, test first, through public interfaces.

# TDD: тест спершу

1. Узгодь поведінку, яку треба отримати (одне речення на випадок). Тестуй поведінку через публічний інтерфейс модуля, а не внутрішні деталі.
2. Червоний: напиши ОДИН тест на найменший шматок поведінки, запусти й переконайся, що він падає з очікуваної причини.
3. Зелений: напиши мінімум коду, щоб тест пройшов. Не додавай того, чого тест не вимагає.
4. Повтори для наступного випадку. Не пиши всі тести наперед.
5. Рефакторинг: лише на зеленому, дрібними кроками, запускаючи тести після кожного.
6. Для бага: спершу тест, що відтворює баг (червоний), потім виправлення.
7. Дотримуйся тестових конвенцій проєкту (місце тестів, фейки, заборона мережі).
