# Один Durable Object і один контейнер на всі сесії агента

**Рішення.** `apps/agent` має один Durable Object `main` (клас `AgentSession`), який володіє єдиним контейнером з OpenCode. Усі сесії агента живуть усередині нього, кожна у своїй теці (для репозиторію — окремий git worktree); id сесії лише ключ у сховищі DO.

**Чому.** Один контейнер дешевший за контейнер на сесію, а всі сесії видно в одному веб-інтерфейсі OpenCode. Диск контейнера тимчасовий, тому стан зберігається знімками диска (`snapshotContainer`).

**Наслідки.**
- Підготовка тек і створення сесій виконуються по черзі (`Computer.serial`): паралельні `git clone` одного репозиторію псують один одного.
- Клас лишається `AgentSession` історично: перейменування потребувало б міграції Durable Object.
- Усередині клас розділено на модулі (`computer`, `posts`, `forms`, `proxy`, `state`, `config`); зовні його бачать як порт `Agent` (`Sessions & Computer & Deploys`).
