# План рефакторингу `apps/agent`

Мета: розібрати `AgentSession` (`infrastructure/container/session.ts`, ~840 рядків, сім ролей в одному класі) на модулі з однією
відповідальністю, не змінюючи поведінки. Клас Durable Object лишається `AgentSession` (перейменування потребує міграції, ADR 0001),
формат ключів у сховищі не змінюється (дані наявних сесій читаються як раніше). Кожен крок — окремий коміт, після кожного
`npm run check` зелений.

## Етап 1: розбиття `AgentSession`

1. [x] **`SessionStore`** (`store.ts`): типізований доступ до записів `session:`, `watch:`, `job:`, `limit:` і пошук сесії за id
   OpenCode, темою чи гілкою. Прибирає дубльовані `storage.list(...).find(...)` із `session.ts` і `posts.ts`.
2. [x] **`Limits`** (`limits.ts`): очікування скидання лімітів Claude (`waitForLimits`, `checkLimits`).
   - [x] *Поза планом, на прохання власника:* прибрано вигляд теми `messages` (`thread-ui.ts`, клавіші внизу теми, `keyView`,
     `pendingReview`, табло, «➕ Нова сесія», `THREAD_UI`, Flagship). Лишився лише classic.
3. [ ] **`Mcp`** (`mcp.ts`): входи OAuth (Сільпо, Календар, Cloudflare), токени для конфігу теки, оновлення токенів у живому
   OpenCode, запит MCP агентом і відповідь власника.
4. [ ] **`Jobs`** (`jobs.ts`): черга прийнятих завдань (`begin`, `resume`, повтори, звіт про збій).
5. [ ] **`Progress`** (`progress.ts`): що бачить власник під час роботи: опис поточної дії, питання агента, іконка й назва теми.
6. [ ] **`Watcher`** (`watcher.ts`): стеження за сесіями (опитування, потік подій OpenCode, ліміти вартості, підсумок).
7. [ ] **Фасад**: в `AgentSession` лишаються RPC-методи порту `Agent`, `alarm` і складання модулів. Оновити ADR 0001, `docs/agent.md`
   і сайт документації (`apps/docs/web/src/content.ts`, `diagrams.tsx`).

## Етап 2 (окремими PR, після етапу 1)

- Єдиний реєстр MCP-сервісів: назва, підпис, промпт, вхід, «вміє змінювати дані». Зараз сервіс додається в ~10 місцях
  (`McpName`, `Tracked`, `StartInput`, `parsePrefixes`, `mcpConfig`, `start`, логіни, HTTP-маршрути).
- HTTP: одна функція для маршрутів OAuth замість трьох копій; прибрати дубль `/sw.js`; веб-запити через чергу завдань, як у чаті.
- `Computer`: винести підготовку тек і MCP-конфігів (`prepare`, `enableMcp`) у `Workspace`; ключі сховища — у `state.ts`.
- `Env`: розділити на групи (контейнер, чат, публікація, MCP).
- `chat`: id сесії в кнопках не з URL, а явно; `threadUi` раз на подію, а не на кожен виклик.
- `application/` для агента: вибір репозиторію, моделі й MCP з `interface/telegram/handle.ts`.
- Правило лінтера на напрямок шарів (`interface` не імпортує `infrastructure` напряму).
- Шаблон report-site — тека з файлами замість heredoc у `new-report-site.sh`.
